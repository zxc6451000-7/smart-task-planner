# API-контракт «Умный планировщик задач»

Версия контракта: **1.0**

Документ согласован всей командой до начала разработки (подход contract-first).
Любое изменение контракта вносится только через Pull Request с ревью Tech Lead.

## 1. Сервисы и порты

| Сервис               | Порт по умолчанию | Базовый URL             |
|----------------------|-------------------|-------------------------|
| Task Service         | 8000              | `http://localhost:8000` |
| Notification Service | 8001              | `http://localhost:8001` |

Формат данных — JSON в кодировке UTF-8 (`Content-Type: application/json`).

## 2. Схема данных `Task`

| Поле          | Тип             | Обязательное | Описание                                    |
|---------------|-----------------|--------------|---------------------------------------------|
| `id`          | string (UUID v4) | да          | Генерируется Task Service                   |
| `title`       | string          | да           | Название задачи, 1–200 символов              |
| `description` | string          | да           | Описание, до 2000 символов, по умолчанию `""` |
| `status`      | enum            | да           | `new` \| `in_progress` \| `done`, по умолчанию `new` |
| `created_at`  | string (ISO 8601) | да         | Время создания в UTC, генерируется Task Service |

Пример:

```json
{
  "id": "3f1c2b8e-6a4d-4e7b-9a51-2d3c4b5a6f70",
  "title": "Подготовить отчёт",
  "description": "Лабораторная работа №2",
  "status": "new",
  "created_at": "2026-09-16T10:15:30.123456Z"
}
```

## 3. Task Service

### 3.1. `POST /api/tasks` — создать задачу

Тело запроса (`TaskCreate`) — задача **без** `id` и `created_at`:

```json
{
  "title": "Подготовить отчёт",
  "description": "Лабораторная работа №2",
  "status": "new"
}
```

| Код | Когда                                       | Тело            |
|-----|---------------------------------------------|-----------------|
| 201 | Задача создана                              | `Task`          |
| 422 | Ошибка валидации (нет `title`, неверный `status`) | описание ошибки |

После успешного создания Task Service отправляет вебхук в Notification Service (раздел 4).
Ошибка доставки вебхука **не влияет** на ответ клиенту — всё равно возвращается 201.

### 3.2. Остальные операции с задачами

| Метод и путь              | Описание                     | Успех                | Ошибки   |
|---------------------------|------------------------------|----------------------|----------|
| `GET /api/tasks`          | Список задач (по `created_at`) | 200, `Task[]`      | —        |
| `GET /api/tasks/{id}`     | Одна задача                  | 200, `Task`          | 404      |
| `PATCH /api/tasks/{id}`   | Частичное изменение `title`, `description`, `status` | 200, `Task` | 404, 422 |
| `DELETE /api/tasks/{id}`  | Удаление задачи              | 204, без тела        | 404      |

Формат ошибки 404: `{"detail": "Task not found"}`.

## 4. Notification Service

### 4.1. `POST /api/webhooks/task_created` — событие «создана задача»

Тело запроса — объект `Task` целиком (раздел 2), без обёрток.

| Код | Когда                     | Тело                       |
|-----|---------------------------|----------------------------|
| 200 | Уведомление зафиксировано | `{"status": "accepted"}`   |
| 422 | Тело не соответствует `Task` | описание ошибки         |

Уведомление «отправляется» записью в консоль и в файл `logs/notifications.log`.

### 4.2. Формат сообщения вебхука

Task Service отправляет запрос:

```http
POST /api/webhooks/task_created HTTP/1.1
Host: localhost:8001
Content-Type: application/json

{"id": "...", "title": "...", "description": "...", "status": "new", "created_at": "..."}
```

Дополнительные заголовки и правила повторной доставки: будут согласованы при разработке.
