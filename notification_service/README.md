# Notification Service

Принимает событие о создании задачи и «отправляет» уведомление пользователю —
пишет его в консоль и в файл `logs/notifications.log` (см. `API_CONTRACT.md`, раздел 4).

## Запуск

Из корня репозитория:

```bash
pip install -r notification_service/requirements.txt
uvicorn notification_service.main:app --port 8001
```

Swagger UI: <http://localhost:8001/docs>. Последние уведомления: `GET /api/notifications`.

| Переменная окружения     | По умолчанию              |
|--------------------------|---------------------------|
| `NOTIFICATION_LOG_FILE`  | `logs/notifications.log`  |

## Тесты

```bash
python -m pytest notification_service
```

`tests/test_webhook.py` покрывает основной сценарий (приём и запись в лог), дубли,
ошибки валидации и недоступность лог-файла.

## Обработка ошибок

- Некорректное тело → 422, сервис продолжает работу.
- Повторная доставка того же события (`X-Event-Id`) → 200 `duplicate`, без второго уведомления.
- Ошибка записи в лог → 503; событие не помечается обработанным, поэтому повтор от Task Service
  будет принят после восстановления.

## Локальные точки отказа

| # | Точка отказа | Последствие | Как обработано / ограничение |
|---|--------------|-------------|------------------------------|
| 1 | Нет прав / нет места / путь к логу — не каталог | Уведомление не записано | 503 + `ERROR` в консоли, Task Service повторит доставку |
| 2 | Невалидное тело от Task Service | Событие отклонено | 422; Task Service не повторяет 4xx — видно в его логе |
| 3 | Повторная доставка после таймаута | Риск двойного уведомления | Дедупликация по `X-Event-Id` (последние 10 000 ключей) |
| 4 | Перезапуск сервиса | Сбрасывается список обработанных событий и история | Ограничение прототипа; в продакшене — хранилище ключей (Redis/БД) |
| 5 | Сервис не запущен | Уведомления не приходят | Повторы на стороне Task Service (до 5 попыток) |
| 6 | Разрастание лог-файла | Заполнение диска | Ротация не реализована — в продакшене `logrotate` / `RotatingFileHandler` |
| 7 | Расхождение схемы `Task` между сервисами | 422 на все события | Схема зафиксирована в контракте, проверяется интеграционным тестом |
