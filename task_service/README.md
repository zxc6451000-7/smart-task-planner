# Task Service

Создание, редактирование, удаление и получение списка задач. После создания задачи
отправляет событие `task.created` в Notification Service (см. `API_CONTRACT.md`).

## Запуск

Из корня репозитория:

```bash
pip install -r task_service/requirements.txt
uvicorn task_service.main:app --port 8000
```

Swagger UI: <http://localhost:8000/docs>. Состояние и счётчики вебхуков: `GET /health`.

Пример запроса:

```bash
curl -i -X POST http://localhost:8000/api/tasks -H "Content-Type: application/json" -d '{"title": "Подготовить отчёт"}'
```

| Переменная окружения       | По умолчанию                                        |
|----------------------------|-----------------------------------------------------|
| `NOTIFICATION_WEBHOOK_URL` | `http://localhost:8001/api/webhooks/task_created`   |
| `WEBHOOK_TIMEOUT`          | `2.0` (с)                                           |
| `WEBHOOK_MAX_ATTEMPTS`     | `5`                                                 |
| `WEBHOOK_RETRY_BASE_DELAY` | `0.5` (с, удваивается с каждой попыткой)            |
| `WEBHOOK_RETRY_MAX_DELAY`  | `10.0` (с)                                          |
| `WEBHOOK_QUEUE_SIZE`       | `1000`                                              |

## Тесты

```bash
python -m pytest task_service
```

- `tests/test_api.py` — CRUD-сценарий, коды 201/404/422, значения по умолчанию.
- `tests/test_notifier.py` — формат вебхука, повторы, отказ Notification Service.

## Обработка ошибок

Событие кладётся в очередь в памяти (`notifier.py`), отправку выполняет фоновый воркер.
Поэтому `POST /api/tasks` отвечает 201, даже если Notification Service недоступен.
Временные ошибки повторяются с экспоненциальной задержкой, после последней попытки
событие пишется в лог с уровнем `ERROR` и учитывается в `/health` → `webhook_failed`.

## Локальные точки отказа

| # | Точка отказа | Последствие | Как обработано / ограничение |
|---|--------------|-------------|------------------------------|
| 1 | Notification Service не запущен / сеть недоступна | Уведомление не отправлено | До 5 повторов, затем `ERROR` в логе; API продолжает работать |
| 2 | Notification Service отвечает медленно | Воркер ждёт ответа | Таймаут 2 с на запрос, запрос API не блокируется |
| 3 | Notification Service отвечает 5xx/429 | Временный сбой | Повтор по той же политике |
| 4 | Notification Service отвечает 4xx | Несовпадение контракта | Без повторов, `ERROR` в логе — нужна проверка контракта |
| 5 | Переполнение очереди (> 1000 событий) | Новое событие теряется | `ERROR` в логе, счётчик `webhook_failed` |
| 6 | Перезапуск / падение процесса | Все задачи и неотправленные события теряются | Хранилище и очередь в памяти — ограничение прототипа; в продакшене нужны БД и брокер (RabbitMQ/Kafka) |
| 7 | Повторная доставка после таймаута | Notification Service может получить событие дважды | Одинаковый `X-Event-Id` во всех попытках — получатель отбрасывает дубли |
| 8 | Несколько экземпляров сервиса | У каждого своё хранилище | Прототип рассчитан на один процесс |
